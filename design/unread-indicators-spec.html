Spec — Unread Document Indicators

Project: AgentDocs vault web UI (packages/web/src/App.tsx) · Status: proposal, awaiting option selection · Date: 2026-08-05

1. Goal

When documents are added or edited in the vault (typically by an agent session via vault add), the open UI must:

  1. Ping the page — surface the unread count at browser-tab level so the user notices without looking at the app.
  2. Mark unread docs in the sidebar — an indicator next to each document the user hasn't seen in its current state.

2. Defining "unread"

The vault is git-versioned: every add/update is a commit on docs/<project>/<slug>. Unread = the doc's latest version is newer than the version the user last opened.

OptionMechanismTradeoffs
A. Compare versions (SHA) — recommended Client stores lastSeenSha per slug. Server exposes latest commit SHA per doc. Unread ⇔ latestSha !== lastSeenSha. Never-opened docs have no stored SHA → unread. Precise: distinguishes "edited" from "new", survives timestamp edge cases. Requires one extra field in the doc list payload.
B. Compare timestamps Server stores an updated ISO timestamp in SQLite at index time; client stores lastSeenAt per slug. Unread ⇔ updated > lastSeenAt. Simpler payload, but clock granularity and identical re-uploads can produce false positives/negatives.
Both options need some server change: the current GET /api/docs returns only {slug, project, title, created}. Option A adds latestSha (from git log -1, computed at index/upload time and cached in SQLite — not per-request, to avoid N git calls).

3. Read-state storage

OptionMechanismTradeoffs
A. Browser localStorage — recommended { "project/slug": "sha" } map, written when a doc is opened. Zero server endpoints. Single-user local app — per-browser state is fine. State lost if browser storage cleared; that's harmless (docs just appear unread again).
B. Server-side (SQLite table) read_state(slug, sha) + POST /api/docs/:slug/seen. Survives across browsers, but adds endpoints and a migration for a single-user tool. Overkill.

Mark-as-read trigger: opening a doc in the main pane (existing select() handler). A "mark all as read" affordance is an optional extra — see §7.

4. Page ping — tab-level unread count

OptionMechanismTradeoffs
A. Title prefix — recommended (with B) document.title = `(3) AgentDocs Vault` when unread > 0. ~3 lines. Visible in tab strip and taskbar. Standard pattern (Slack, Gmail).
B. Favicon badge — recommended (with A) Redraw favicon on a canvas with a red count bubble; swap the <link rel="icon"> href. ~25 lines, no deps. Catches the eye even with a pinned/narrow tab where the title is hidden.
C. Audible ping / toast Play a sound or show an in-app toast when unread count increases while the tab is open. "Ping" read literally. Sound requires prior user interaction (autoplay policy) and can annoy. Suggest skipping unless wanted.

6. Freshness / live updates

Observed issue: a document added via vault add while the UI is open does not appear until a full page refresh — load() only re-runs when the search query or project filter changes. This is a standing gap independent of unread indicators, and the fix below resolves both at once.

Unread state depends on detecting changes while the page is open. Current load() runs only on search/filter change.

OptionMechanismTradeoffs
A. Poll GET /api/docs — recommended setInterval every ~5s reuses the existing load(). Diff latestSha values against previous fetch to detect "changed while open" (drives the pulse + optional toast). Local single-user server; a 5s poll of an in-memory SQLite query is free. No new infra.
B. SSE / WebSocket push Server emits an event on each upload. Instant, but a persistent connection and event plumbing for a local tool — disproportionate.

7. Scope decisions needed

  • Indicator style: pick from §5 (recommendation: dot + group count, or pills).
  • Ping: title prefix + favicon badge assumed; confirm or adjust (audible ping? in-app toast on live change?).
  • Mark-all-read button: in scope? (One line in the sidebar header; without it, clearing 20 unread docs means opening each.)
  • Collapse-aware groups: auto-expand groups containing unread docs on load, or rely on the group count chip?
  • Viewing an old version counts as read? Proposal: any open of the doc marks the latest SHA as seen, regardless of the ?sha= being viewed.

8. Implementation sketch (post-decision)

Assuming recommended options (SHA compare, localStorage, title + favicon ping, dot + group count, 5s poll):

  1. server/db.ts — add latest_sha column to FTS table (or a side table); populate in upsertDoc from git; migration = POST /api/reindex.
  2. server/index.ts — pass latest SHA into indexDoc at upload; no new endpoints.
  3. web/App.tsx —
    1. seenRef: localStorage map project/slug → sha, loaded once.
    2. Poll load() every 5s; compute unread set from latestSha !== seen[slug].
    3. select() writes the doc's latest SHA to the map → indicator clears.
    4. Title prefix + favicon badge effect driven by unread.size.
    5. Dot in doc row, count chip in ProjectGroup header; pulse class on docs whose SHA changed since previous poll.

Estimated footprint: ~15 lines server, ~70 lines client, no new dependencies.
